开源我的投研工作流：analyst-research 是怎么设计的

Gen · 开源 · MIT · Claude Code 插件

我把自己写研报用的工作流开源了——一个叫 analyst-research 的 Claude skill。它不是「帮你写两段分析」那种，而是把一份投研报告从假设到成稿的完整流程、连同那套本该有的纪律，全部写进了 skill 里。

这篇不讲它能干嘛（主页有），只讲一件事：它是怎么设计的。

先有一个判断：把 AI 当成初级分析师

我对 AI 的定位很明确：一个初级分析师——快、知识面广，但直觉没经过训练，会想当然、会编数字、会把估算说成事实。

既然如此，我的工作就不是「让它更聪明」，而是给它铺一条轨道，让它在轨道里跑，并在错误进入正文之前拦下来。analyst-research 的所有设计，都是从这个判断出发的。

设计一：三档 mode，一次触发自适应

项目体量差别很大：有时只要一页备忘，有时要一篇 1.5 万字的旗舰报告。所以我没做「一个万能流程」，而是做了三档，触发时选一档：

light — 5 页决策备忘，6 步，不带图，十几分钟。

medium — 10-15 页主题分析，8 步，3-8 张图。

heavy — 1.5 万字旗舰报告，11 步，20+ 图，可选多 LLM。

关键是：skill 只加载你选中那一档的工作流——既不让小项目背上重流程，也不浪费 context。

设计二：把「严谨」写进 8 步，而不是嘴上提醒

严谨没法靠「提醒 AI 要严谨」实现，得写进结构。以 medium / heavy 的 8 步骨架为例（标〔人工〕〔质量门〕的是写死的停点）：

① 锁定假设 〔人工〕
一句话研究问题，动手检索前就定死，全程跟着走，绝不从草稿反推。

② 广谱检索
五类来源（官方统计 / 多边机构 / 央行 / 卖方 / 公司原始披露），PDF 整篇下，不只看摘要。

③ 提纲 + 配图规划 〔人工确认〕
结构和配图先给人过目、确认了再动笔。

④ 取数 + 出图
每张图一组 CSV + 脚本，标题里的数字必须和图上的数据对得上。

⑤ 一气呵成写初稿
单 LLM 从头写到尾，边写边标引用，绝不写完再补。

⑥ 自我批评，6 维度 〔质量门〕
事实 / 单位 / 引用 / 连贯 / 论证 / 语言，查三轮，不过关打回第 5 步。

⑦ 独立核验 〔质量门〕
每个撑结论的数字交叉核对，核不过就标存疑或删掉。

⑧ 定稿签字 + 派生 〔人工〕
人读完整篇、签字，再派生公众号 / HTML / Word。

那几个〔人工〕〔质量门〕是写死的：AI 跑得再顺，关键处也得停下等人。

设计三：四条不可妥协的原则

来源可追溯。任何数字追到原始来源，追不到就标存疑并剔除——绝不写进结论。宁可写「未公开」，也不给一个看似合理的猜测。

三态标注。事实 / 估算 / 推断用不同措辞分清楚，绝不混为一谈。

AI 是副驾，不是主驾。假设、scope、最终签字都由人决定。

持续迭代。每个项目以复盘收尾，经验证的经验再回流进 skill 本身。

设计四：让不同 LLM 干各自最擅长的（heavy，可选）

Claude — 英文 IB 级写作、搭结构、做整合、端到端编排，每一步的默认模型。

GPT-5 — 数值精度、单位一致、事实核验、语言风格红线，第 6 步唯一的外部批评者。

DeepSeek — 中文润色的路数，已提炼成风格指南，现由 Claude 直接套用。

这个 skill 怎么组织的

一个触发入口，三套工作流，共用一套生产工具：

analyst-research/
├── SKILL.md              触发 + mode 分流
├── references/
│   ├── workflow_light    6 步
│   ├── workflow_medium   8 步
│   ├── workflow_heavy    11 步
│   └── report_style_spec 视觉生产规范
└── scripts/
    ├── chart_template.py 统一图表样式
    └── publication-style 公众号 / HTML 模板
